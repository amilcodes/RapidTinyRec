# Small beam-state helper replay pilot candidate

This isolated candidate captures the original HF 4.55.4 running-beam and finished-beam helpers. It has no measured CUDA correctness or latency result yet. It starts from the accepted folded/profile branch, without rejected packed-MLP or constraint-replay behavior.

The existing folded replay traces at prompt lengths 76, 101 and 121 contain ten calls to these two helpers per request. They launch 195 GPU events and contain 645 nested CPU operations. Linked GPU activity totals 0.504–0.514 ms while instrumented host sections span 7.129–7.460 ms. These are overlapping views with profiling overhead, not a predicted saving. A paired generation-call pilot must establish whether capture helps.

The running helper performs the original top-k on 100 candidate scores; the finished helper performs its original penalties, concatenation and top-k on 150 scores. Captures invoke the pinned bound methods, not copied or fused arithmetic. Source hashes verify both helpers, their gather dependency and the surrounding beam loop. Both full-vocabulary normalizations, vocabulary-wide top-k, SID constraints, all five probabilities, saved-score clones, termination logic and model/cache behavior remain unchanged.

Each model instance gets two reversible wrappers. A generation lease enforces running/finished pairs across five steps. Separate graph-private pools and owned staging tensors preserve state for each helper, prompt length and step. All dynamic inputs are copied before replay, including recurrent finished-beam state. Returned tensors are borrowed until the caller extracts final sequences, scores and transitions and closes the lease; overlapping requests are rejected. This supports one sequential CUDA stream. Immutable scalar arguments, tensor shapes, strides, dtypes and devices are part of the graph key. Sequence capacity is prompt+8 even though this workload produces five tokens.

The expected initial capture count is 20 helper graphs for the two-length pilot and 100 for the ten-length full cohort, additional to 8/40 model graphs. The benchmark must check actual counts, all storage and capture events, and freeze before timing. Graph input/output logical and unique bytes exclude intermediate private-pool overhead, which allocator residency/peaks must also report. Model loading is separate; setup includes nested preparation, compilation, warmup and capture intervals and those must not be added.

CPU tests exercise the actual pinned helper functions with tied, equal, nearly equal and infinite scores, different length penalties and stopping flags, changed inputs, recurrent state, ownership, lifecycle guards and wrapper restoration. These do not establish CUDA graph correctness or GPU tie stability. The paired benchmark includes seven synthetic GPU probe scenarios over four mixed-length requests each: equal scores, kth-boundary ties, signed zeros, near ties, infinities, finished flags and nonzero length penalty. Each invokes the original methods directly and through replay; compressed raw output values, bit/ancestry comparisons and per-step retained state are preserved. The independent auditor recomputes raw comparison counts and checks every staging tensor shape, stride, dtype, scalar, graph count and storage total. Any discrepancy remains a failed gate.
